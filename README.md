# 모로가도 · 바톤 메이커 + 상세페이지 v10 통합본

바톤 메이커 v15에서 바톤을 만들면, 결과 화면으로 **상세페이지 v10 디자인**이 열려요.
메이커에서 입력한 제목·이미지·노트·팔레트·규격·태그·진척도·파일·아이디어가 그대로 채워져요.

## 이번 수정 (헤더 · 바톤 노트 · 진척도 색 · 전환)

- **헤더**: 피그마 3516:27799처럼 아래 탭 영역에 저장 · 알림 · RUNNER 김찬우 님 · 프로필을 넣었어요. 헤더가 접혀도 이 탭은 남아요. 메뉴 세 번째는 "바톤 올리기"(현재 페이지)예요.
- **바톤 노트**: 피그마 3666:4124 새 디자인. 노트 위 말풍선(AI 초안 안내), "AI로 초안 쓰기 / 다시 쓰기 · 지우기", 글자 수, 바톤노트 가이드(질문 7개, 펼치면 설명 · 예시 · 글에 넣기), 구분선, 이어받을 아이디어.
- **폰트**: 피그마의 Noto Sans KR 대신 Spoqa Han Sans Neo. `fonts.css`에 폰트를 넣어서 인터넷 없이도 같은 글꼴로 보여요 (SIL OFL 1.1).
- **진척도 색**: 진척도를 고르면 업로드 페이지의 초록 요소가 모두 그 단계 색으로 바뀌어요. 색 값은 `ambient.js`의 `accents`, CSS에서는 `--accent` 계열 변수예요. 초록이 들어간 아이콘은 `assets/tint/<단계>/`의 색 바뀐 사본으로 교체돼요. 헤더 로고 · 프로필 원은 브랜드 요소라 그대로 둬요.
- **파일 정보 → 바톤 노트 전환** (`note-snap.js`): 파일 정보 카드 끝에서 스크롤을 내리면 약 1.5초 동안 천천히 내려가며 전환 문구와 노트 카드가 아래에서 밀려 올라와요. 노트 맨 위에서 스크롤을 올리면 같은 속도로 파일 정보로 돌아가요. 휠 · 트랙패드 · 키보드 · 터치 모두 같은 방식이에요.
- **일러스트 재조색**: Planting 원본(#00F998 / #2AB57F / #A6FDDB)의 명도·채도 관계를 OKLCH로 유지하고 색상만 단계 색으로 옮겼어요. 진한 톤은 자연스럽게 따뜻한/푸른 쪽으로 살짝 이동해요.
- **상세페이지 꽉 채우기**: 1440×1024 시안을 화면 너비에 맞춰 확대·축소해요(`baton-render.js`의 MorogaroFit). 프레임이 화면보다 길면 끝까지 스크롤한 뒤 바톤로그로 넘어가요.

## 흐름

파일 올리기 → 소스 확인 → … → 바톤 노트 → **이대로 업로드 / 상세페이지로** → 바톤 만들기
→ v10 상세페이지(바톤 정보 · 파일 목록 · 바톤 너머) → **바톤 수정하기** 또는 ‹ 버튼 → 메이커로 돌아가 이어서 수정

- 실행 방법은 이전과 같아요. `index.html`을 열거나, AI 기능까지 쓰려면 `bash start.command`.
- 만든 바톤은 이 브라우저(IndexedDB)에 저장돼요. 주소(`#baton/…`)로 새로고침해도 다시 열려요.
- 보관(북마크) 버튼은 바톤 기록에 저장돼요.

## v15 변경 요약

- 상세페이지의 기준을 Figma `3625:3446`으로 갱신했습니다. 이미지 갤러리와 오른쪽 파일 모양 정보 카드를 유지하며, 하단의 흰색 곡선 배경은 제거했습니다.
- `파일 목록` 탭은 Figma `3635:3855`의 별도 앞/뒤 SVG 레이어를 사용합니다. 상단의 진척도 일러스트·확인 근거, 구분선, 파일명/형식/용량, 개별 다운로드와 `전체다운`을 연결했습니다.
- 파일·썸네일·노트·진척도 값은 실제 업로드 자료와 사용자가 수정한 값입니다. 피그마 예시의 `3D 모델링`, `소재 4종` 같은 문장을 임의로 채우지 않습니다. 직접 고른 단계에는 `작성자가 직접 선택한 진척도예요.`라고 표시합니다.
- 헤더의 흰색 면 아래에 겹쳐 있던 초록색 레이어를 HTML에서 제거했습니다. 이전에 확정한 헤더 구성과 맨 위에서만 펼치는 동작은 유지합니다.

### API 없이 배경색 확인하기

**배경의 색상 전환은 브라우저의 JavaScript/CSS만 사용합니다. API 키나 Python 서버가 필요하지 않습니다.**

1. `index.html`을 브라우저에서 엽니다.
2. 이미지나 텍스트 파일을 올린 뒤 `다음으로`를 누릅니다.
3. `소스 확인` 안의 `바톤 진척도`에서 Seeding / Planting / Growing / Blooming을 누릅니다.
4. 선택 즉시 상태가 갱신되고 배경은 약 1.1초에 걸쳐 해당 색으로 전환됩니다. 이 선택 때문에 API를 호출하지 않습니다.
5. 결과 상세페이지에도 같은 단계와 배경색이 이어집니다. `파일 올리기`로 돌아가면 다시 회색입니다.

AI가 파일의 의미를 판단해 진척도를 **제안**하는 것은 별도의 선택 기능입니다. 자동 제안 없이 직접 단계를 정해도 색상·표시·상세페이지 반영이 동작합니다. Flowering의 서비스 선정 규칙과 파일 하나만 올려도 준비율 50%가 되는 규칙은 변경하지 않았습니다.

### 파일 전체 다운로드

`전체다운`은 원본 파일들을 하나의 ZIP에 묶습니다. 서버로 보내지 않고, 원본 바이트를 변환하지 않는 STORE 형식입니다. UTF-8 한글 이름을 지원하고 동일한 이름에는 번호를 붙입니다. ZIP은 원본 크기와 비슷합니다.

현재 한 번에 원본 총 100MB / 1,000개까지 지원합니다. 범위를 넘으면 개별 다운로드를 안내합니다. 폰트 바이너리는 직접 배포하지 않으며, URL은 파일과 별도 목록으로 표시합니다. 오류나 취소 시 다운로드 완료로 표시하지 않습니다.

## 1. 먼저 열어보기

압축을 새 폴더에 풀고 `morogaro-upload/index.html`을 브라우저에서 여세요. 별도 빌드가 필요하지 않습니다. 파일을 넣고 `다음으로`를 누르면 기본 추출 결과를 확인하고 노트와 아이디어를 직접 작성할 수 있습니다. 모든 코드·CSS·assets 폴더를 함께 두세요.

PDF·문서 해석, 실제 AI 분석과 AI 노트 제안까지 사용하려면 Python 3.11 이상 환경에서 프로젝트 폴더의 터미널로 실행합니다.

```bash
bash start.command
```

브라우저 주소: `http://127.0.0.1:8000`

기존 버전의 `.env`를 쓰고 있었다면 **본인 기기에서만** 새 프로젝트 폴더로 옮기세요. ZIP에는 비밀 키가 없으며 `.env.example`만 있습니다. 서버를 종료하려면 실행한 터미널에서 `Control + C`를 누릅니다. HTML 더블클릭만으로는 서버 AI를 호출할 수 없습니다.

API 키 설정 예:

```dotenv
OPENAI_API_KEY=본인의_실제_키
OPENAI_MODEL=gpt-4.1-mini
```

키는 서버에서만 읽습니다. API 사용료는 별도이며, 실제 자료를 보내기 전에 AI 동의를 받습니다. 기본 추출은 OpenAI에 보내지 않습니다. 참고: https://developers.openai.com/api/docs/guides/structured-outputs

## 2. 기존 화면과 유지한 기능

### 규격

왼쪽 `직접 입력` / 기준 파일 드롭다운을 제거했습니다. 가로·세로·단위는 여전히 편집할 수 있습니다. 확인 가능한 첫 규격을 초기값으로 사용하고, 모르는 치수는 비워 둡니다. 단위 변경 시 수치는 자동 환산하지 않습니다.

### 회색 → 진척도 색상 배경

- 파일 올리기 화면은 #FAFAFA 바탕 위의 회색 그라디언트입니다. 파일만 올려 준비율이 50%가 되어도 회색을 유지합니다.
- 소스 확인 화면에서 진척도가 정해지면 약 1.1초에 걸쳐 해당 색상으로 전환합니다. 직접 진척도를 바꾸면 배경도 따라 바뀝니다.
- Seeding #00FFEE / Planting #00F998 / Growing #E3EA2D / Blooming #F9B200. Flowering #FF4093 매핑은 향후 서비스 선정 상태를 위한 예약값이며, 여기서 사용자/AI가 선정하지 않습니다.
- 진척도가 미확인이거나 파일 올리기로 돌아가면 회색입니다.
- 이동 속도는 기존과 같은 14초/편도, 모바일 16초/편도입니다. 동작 줄이기 설정에서는 움직이지 않습니다.

### 6단계 바톤 노트

Figma `3516:28759` 내부의 `3579:35` 구성을 사용했습니다. 노트, 선택형 이야기 확인, 이어받을 아이디어(최대 3개)가 있습니다. 300자는 권장 분량입니다. 편집기는 최대 5,000자까지 보관하며, 질문 6개를 모두 채워야 진행하는 제한은 없습니다.

AI 초안과 아이디어는 사용자가 버튼을 누르고 동의했을 때만 새 요청을 보냅니다. 서버 API 키가 없으면 원고를 만든 척하지 않고 직접 작성 안내를 표시합니다. 초안은 확인된 제목·분류·제작 정보와 추출 근거를 사용합니다. 개인적인 중단 이유나 경험을 지어내지 않도록 요청하고, 반환된 근거 ID가 잘못되면 해당 문장을 제외합니다. 모든 의미적 정확성을 기계적으로 보증하는 방식은 아니므로 작성자가 최종 문장을 확인해야 합니다.

이미 쓰던 노트는 AI 응답으로 덮어쓰지 않습니다. 새 초안을 적용하거나 지울 때 확인창이 나타납니다. AI 아이디어도 기존 아이디어를 교체하지 않고 사용자가 선택해 담습니다.

노트/아이디어/체크리스트/레퍼런스 이미지는 기존 임시 저장 데이터에 함께 보관됩니다. 이전 화면과 다시 분석을 오가도 직접 수정한 값은 유지합니다.

### 결과 상세페이지

Figma `3625:3446`의 이미지 갤러리 + 파일 모양 정보 카드 구성을 실제 입력값으로 채웁니다. 기존 승인 헤더를 사용하고, 폐기된 RUNNER 유료 등급은 되살리지 않습니다.

- 선택한 썸네일 순서와 대표 이미지가 이어집니다. 원본에 없는 예시 이미지를 넣지 않습니다.
- 제목·카테고리·사용 툴·기간·바톤 노트·레퍼런스·팔레트·규격·스타일 태그·아이디어·폰트 정보를 반영합니다.
- 긴 노트는 5줄로 먼저 보여주고 `노트 더 보기`로 펼칩니다.
- `바톤 정보 / 파일 목록` 탭과 이미지 선택·확대가 동작합니다. 일반 원본 파일의 다운로드 링크도 연결됩니다. 폰트 바이너리는 다운로드로 배포하지 않고 공식 받는 곳 링크로 안내합니다.
- `바톤 수정하기`로 돌아가도 현재 작성 내용이 유지됩니다. 다른 작성 중인 바톤과 연결된 옛 기록은 실수로 덮어쓰지 않도록 편집을 막습니다.

## 3. 저장과 공개 범위 — 중요

**현재 `바톤 만들기`는 브라우저 안에 결과 기록을 만드는 동작입니다. 인터넷에 공개 업로드하는 기능은 아닙니다.** 확인창과 상세페이지에 이 사실을 표시합니다.

원본 File 객체와 선택한 썸네일, 입력값을 IndexedDB `morogaro-baton-results` / `batons`에 함께 저장합니다. 임시 저장은 기존 `morogaro-baton-maker` 저장소를 유지하므로 서로 덮어쓰지 않습니다. 서버에 공개 발행하는 API나 다른 사람에게 전달할 공개 URL은 아직 없습니다. `#baton/…` 주소는 **같은 브라우저·같은 출처**에 보관된 기록을 가리키며, 공유 링크가 아닙니다. 브라우저 데이터 삭제/비공개 모드/저장 공간 문제로 기록이 지워질 수 있습니다.

저장에 실패하면 성공으로 표시하지 않습니다. 작성 내용이 남은 상태에서 `저장 없이 미리보기`를 선택할 수 있습니다. 이 미리보기는 새로고침 뒤 복원되지 않습니다. 공유·계승·바톤로그 영역도 공개 서버에 연결되었다고 가장하지 않습니다. 계승/댓글로 새 노드나 반응을 만들어내지 않습니다.

## 4. 기존 기능

원본 파일 업로드, 드래그 앤 드롭, URL 정리, 준비율 50%, 맨 위에서만 펼치는 헤더, 박스 없는 6단계 스탭퍼와 데스크톱 스티키, 로딩 애니메이션, 파일 추출/AI 분석은 유지합니다.

파일 해석 한계도 기존과 같습니다. 암호/손상 파일, 비공개 바이너리 형식, 내보낸 미리보기가 없는 원본 등은 완전히 해석할 수 없습니다. 확인하지 못한 내용은 추출한 것으로 표시하지 않습니다. 일부 형식은 FFmpeg/LibreOffice/선택 패키지가 필요합니다. 서버의 `/api/config`가 현재 실행 환경에서 가능한 범위를 반환합니다.

화면의 고정 서체는 **Spoqa Han Sans Neo** 공식 웹폰트입니다. 별도 폰트 파일은 동봉하지 않습니다. 외부 웹폰트 서버 접근이 막힌 환경에서는 대체 글꼴을 사용합니다.

## 5. 수정할 파일

| 목적 | 파일 |
|---|---|
| 배경의 색상/속도/전환 | `ambient.css`, `ambient.js` |
| 바톤 노트의 배치/인터랙션 | `note.css`, `note.js` |
| AI 초안 프롬프트/검증 | `note_ai.py`, `server.py`의 `/api/baton-note` |
| 상세 결과 화면/로컬 결과 저장 | `detail.css`, `detail.js` |
| 클라이언트 파일 ZIP 다운로드 | `download-bundle.js` |
| 6단계 이동/현재 단계 | `stepper.css`, `stepper.js` |
| 분석 결과와 편집 모델 연결 | `review.js`, `review.css` |
| 기존 파일 추출 | `file-analysis.js`, `analysis_engine.py`, `file_extractors.py` |

주요 데이터 필드는 `MorogaroReview.getData()`에서 확인할 수 있습니다. 기존 필드에 `batonNote`, `nextIdeas`, `noteChecklist`, `noteDraft`, `references`가 추가됩니다. 노트 체크리스트는 본문을 자동 채점하는 결과가 아니라 작성자의 선택입니다.

기존 `morogaro:publish-request`와 `morogaro:review-next` 이벤트는 유지했습니다. `detail.js`가 이를 처리합니다. 실제 발행 API로 전환할 때는 이 로컬 처리부를 교체하고 인증/권한/업로드 검사/저장/공개 URL/계승 규칙을 서버에서 구현하세요. 현재 Python 서버는 127.0.0.1의 로컬 개발용입니다. 인증 없이 공개 배포하지 마세요.
